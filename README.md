# Knowledge Base

A central, version-controlled home for documentation, how-tos, reference notes, and decisions. It is meant to be the single place the team (and our tools) look to find accurate, up-to-date answers.

## Purpose

- Capture shared knowledge so it doesn't live only in people's heads or chat threads.
- Give humans and AI assistants a consistent source to search and cite.
- Keep a reviewable history of how our knowledge changes over time.

## What belongs here

- **Guides and how-tos**: step-by-step instructions for recurring tasks.
- **Reference**: definitions, glossaries, configuration, and conventions.
- **Decisions**: short records of what was decided, why, and when.
- **Runbooks and FAQs**: troubleshooting steps and common questions.

## Conventions

- Write in Markdown, one topic per file, with a clear title and a one-line summary at the top.
- Use lowercase, hyphenated file names (e.g. `onboarding-checklist.md`).
- Group related files in folders by topic.
- Link to related pages instead of duplicating content.
- Keep pages current: update or remove outdated information when you spot it.

## Contributing

1. Create a branch and add or edit pages.
2. Open a pull request for review.
3. Merge once approved.
